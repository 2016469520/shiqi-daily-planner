# 手机端全面体检报告（v1.1.7）

> 面向手机浏览器 / 加壳 WebView（安卓）/ iOS Safari 的一次系统排查与修复记录。
> 所有结论都来自真机尺寸的自动化测量，不是肉眼截图推断。

## 怎么查的

用静态产物（`BUILD_STATIC=1` 导出的 `out/`）当手机站点跑，Playwright 按五种机型尺寸打开全部 11 个页面，
逐元素量尺寸、量遮挡、量字号，并注入真实感的种子数据（含超长英文串、跨天任务、收集箱、习惯记录、倒数日）。

机型档位：`320×568`（极窄）、`360×640`（小屏安卓）、`375×667`（iPhone SE）、`390×844`（iPhone 13/14，底部安全区 34px）、`412×915`（大屏安卓）。

检查项：

- 文档级与元素级横向溢出
- 可点击元素命中区（< 44×44 记为过小）
- 正文字号（< 12px 记为过小）
- 输入控件字号（< 16px 会触发 iOS 聚焦放大）
- 滚到底后是否仍被底部导航遮挡
- 悬浮（hover）才显示的控件在触屏上的可见性
- 弹窗 / 抽屉高度是否溢出屏幕、底部按钮是否可达

## 查到的问题与修法

### P0 · 功能不可达

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 手机上进不去统计 / 复盘 / 每日总结 | 底部导航只有 5 个入口，这三页只能手打 URL | 底部导航新增「更多」，抽屉里放统计、复盘、每日总结、收集箱、倒数日 |
| 日视图任务操作菜单触屏不可见 | 「更多操作」（编辑/复制/上下移/删除）写死 `opacity-0 group-hover:opacity-100`，触屏没有 hover，入口等于不存在 | 抽出 `.hover-reveal`：仅在 `(hover: hover) and (pointer: fine)` 下隐藏，触屏常显 |
| 周视图拖拽把手、子任务删除按钮同样不可见 | 同上 | 同上 |
| 月视图在手机上不可用 | 每格仅 55px 宽，四条任务被压成「完…」「Su…」，且格内还套了一层独立滚动 | 窄屏改为「最多两条 + 剩余条数」，点格子进日视图看全部；格内滚动只在桌面保留 |
| 任务详情抽屉底部的「删除」点不到 | 抽屉正文 `div` 只有 `overflow-y-auto`，没有 `min-h-0 flex-1`，被内容撑高后把删除顶出屏幕且滚不到 | 补 `min-h-0 flex-1`，正文成为真正的滚动容器 |

### P1 · 布局与安全区

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 底部导航盖住最后一屏内容 | 内容区固定 `pb-16`（64px），iPhone 上手势条让导航实际高 90px | 改为 `calc(3.5rem + env(safe-area-inset-bottom))` |
| 顶部状态栏压住页面标题 | `viewport-fit=cover` 但没有任何顶部安全区处理（PWA 全屏、安卓 edge-to-edge 都会压） | 滚动区补 `padding-top: env(safe-area-inset-top)` |
| 手机浏览器地址栏收起时页面底部被吃 | 外壳用 `100vh` | 改用 `100dvh`（保留 vh 兜底） |
| 弹窗在小屏上下同时溢出 | `DialogContent` 只有居中定位，没有 `max-height`，568 高屏上标题和保存按钮都在屏外 | 统一加 `max-height: calc(100dvh - 2rem)` + 内部滚动 |
| 底部抽屉最后一行被手势条盖住 | 抽屉没有底部安全区内边距 | 抽屉/底部弹层补 `padding-bottom: env(safe-area-inset-bottom)` |
| 设置页分组横滑被硬切 | 7 个分组在一行里横滑，右侧被切掉 42px 且没有任何「还有更多」提示 | 窄屏改为换行铺开，7 组全部可见 |
| 长英文/长串标题冲出卡片 | 无空格长串不断行，直接盖住右侧时段徽标 | `body { overflow-wrap: break-word }`，只在放不下时断行 |
| Fluent 主题弹层在半透明下穿帮 | 云母面板 92% 不透明 + `backdrop-filter`，设备不支持模糊时背后文字直接透上来 | 提高到 97%，支持模糊时观感不变，不支持时也可读 |

### P2 · 可点性与可读性

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 小图标点不准 | 卡片关闭 22×22、习惯编辑/删除 28×28、步进器 32×32 | 新增 `.tap-pad` / `.tap-pad-sm`，用伪元素把命中区外扩到 40~46px，视觉尺寸不变 |
| iOS 聚焦输入框会把整页放大 | 输入框 14px / 下拉 12px | 触屏下统一 16px（`@media (hover:none) and (pointer:coarse)`） |
| 11px 小字在手机上读不动 | `text-micro` 全站 11px | 窄屏兜底到 12px，用 `max()` 保留用户自己的「字号倍率」设置 |

## 修完之后

同一套脚本复跑：

- 五个尺寸 × 11 个页面：**横向溢出 0、滚到底被导航遮挡 0、输入控件小于 16px 0**
- 交互验收 11 项全过（导航 6 入口、「更多」抽屉 5 页、命中区、长串折行、抽屉不溢出、抽屉删除可达、日视图操作可见、月视图 +N、月视图无嵌套滚动、新建习惯弹窗完整可见、无 JS 报错）
- 桌面端回归：1280×800 下无底部导航、无安全区 padding、月视图格子仍可滚动且不截断、悬停显隐仍是「默认 0 → 悬停 1」
- `tsc` 无错、`eslint` 0 error、382 个单测全通过

## 仍在的已知限制

- **安卓系统返回键**：加壳版本目前没有接管返回键（需要 `@capacitor/app` 插件 + 重新同步原生工程），本次只修 Web 层，未动原生壳。
- **月视图标题**：手机上格子只有 55px 宽，长标题仍然会截断（信息密度所限），点格子进日视图可看全文。
- **设置页主题卡内的 9~10px 标签**：属于缩略预览里的装饰性小字，未随正文一起抬字号。
