# SPEC — 习惯/倒数日/快速新增/专注交互改进

## 1. 习惯不同计量方式的正确交互

### 当前问题
所有习惯计量方式共用同一套"点击打卡"交互，对 `duration`（分钟）和 `numeric`（自定义数值）不合理——用户不可能每分钟点一次。

### 计量方式映射
- `boolean`：完成/未完成 → 勾选切换
- `count`：次数 → +/- 1 调整 + 直接输入
- `duration`：分钟 → 直接输入分钟 + 快捷按钮（+5/+10/+15/+30）
- `numeric`：自定义数值 → 直接输入 + 加减步进

### 各类型打卡 UI

#### boolean
- 显示：完成 ✓ / 未完成 ○
- 点击切换状态
- 完成时 value = target_value, is_completed = true
- 取消时 value = 0, is_completed = false

#### count
- 显示当前值 / 目标值
- -1 按钮 | 当前次数 | +1 按钮
- 可直接点击数字输入新值
- 达到目标时自动标记完成

#### duration (minutes)
- 显示当前分钟 / 目标分钟
- 快捷按钮：+5, +10, +15, +30
- 直接输入分钟数
- 达到目标时自动标记完成

#### numeric
- 显示当前值 / 目标值 + 单位
- +/- 步进按钮（步进值根据单位合理设置）
- 直接输入数值
- 达到目标时自动标记完成

## 5. 快速新增 placeholder 策略

### 当前问题
时段初始显示"上午"，难度初始显示"一般"，用户误以为已明确选择

### 改造方案
- 时段初始显示"选择时段"（placeholder），用户选择后显示"上午/下午/晚上"
- 难度初始显示"选择难度"（placeholder），用户选择后显示"简单/一般/困难/极难"
- 状态：period 初始值改为空字符串 `''`，difficulty 初始值改为空字符串 `''`
- 保存 fallback：未选择时段时根据当前时间推断（6-12→morning, 12-18→afternoon, 18-6→evening），未选择难度时默认 `medium`
- SelectValue 当 value 为空时显示 placeholder

## 7. 专注正计时（Stopwatch）

### 模式
- **倒计时（countdown）**：设定目标时长 → 倒计时到 0 → 完成
- **正计时（stopwatch）**：从 00:00 开始 → 累计 → 手动完成

### UI
- 模式切换：倒计时 | 正计时
- 正计时：显示已用时间（MM:SS），从 0 开始
- 控制：开始、暂停、继续、完成、放弃

### 状态机
- ready → running → paused → completed/cancelled
- 正计时也支持暂停和继续
- 刷新后恢复正确时间

### 时间计算
- 基于 started_at + paused_at + accumulated_seconds + current time
- 正计时：elapsed = accumulated + (now - resumed_at)
- 倒计时：remaining = planned - elapsed

### 数据结构
- FocusSession 新增 `timer_mode` 字段：`'countdown' | 'stopwatch'`
- 迁移：旧记录默认 `countdown`
- Stopwatch 的 planned_minutes 可为 0（不设目标）

### 统计
- completed → 计入统计
- cancelled → 不计入统计
- 正计时完成后 actual_seconds 为实际用时，计入所有统计维度

8. 专注时长支持滚轮、滑块、输入调整
9. 专注支持倒计时和正计时
10. 正计时刷新后恢复正确
11. 所有显示为中文
