# SPEC — 日历、专注、设置工作区优化

## 当前问题

1. **周视图任务拥挤**：同一天同一时段任务多时，卡片相互遮挡、日期列错位、不同日期时段高度不一致
2. **日历任务无法点击查看详情**：周视图的 DraggableTaskChip 只有拖拽功能，没有 onClick 打开详情
3. **英文/内部值直接显示**：morning、afternoon、evening、none、normal、month、week、day、0、Sun 等直接渲染
4. **"紧急程度"语义不合理**：用户手动选择优先级，应改为"任务难度"；紧迫度应根据截止时间自动计算
5. **专注功能报错/不能正常使用**：入口过小，需升级为一级功能
6. **缺少专注统计和个性化展示**
7. **"每日总结"入口从导航消失**：当前导航只有"复盘"进入历史，无直接入口
8. **设置页布局**：`max-w-2xl` 导致桌面端内容挤在左侧

## 日历高密度显示规则

- 周视图每单元格最多显示 3 条紧凑任务卡片
- 月视图每日期格最多显示 3 条任务
- 超出显示"还有 N 项"
- 点击"还有 N 项"打开该日期时段的所有事项列表（桌面侧边/手机全屏）
- 不在单元格内部使用永久滚动条
- 上午、下午、晚上三行统一行高
- 7 个日期列严格对齐
- 小屏：保持最小列宽，横向滚动，不压缩七列

## 日程详情交互

- 桌面端：右侧 Sheet/侧边详情面板，日历保持可见
- 手机端：全屏详情页
- 点击任务打开详情，不误触完成按钮或拖拽
- 详情可编辑：标题、说明、状态、日期、时段、时间、标签、难度、紧迫度、子任务、重复规则、提醒、预计/实际用时、专注记录

## 难度与紧迫度

### 难度 (difficulty)
- 用户主观选择，值：easy, medium, hard, very_hard
- 默认 medium
- 紧凑界面显示"难度"

### 紧迫度 (自动计算)
- 基于 due_at 实时计算
- 已逾期：超过 due_at 且未完成
- 紧急：距截止 ≤24h
- 较紧急：距截止 ≤3天
- 近期：距截止 ≤7天
- 时间充足：>7天
- 无截止：不显示
- 已完成/已取消：不显示紧迫度
- 纯函数计算，不存储

### 数据迁移
- 新增 difficulty 字段到 tasks
- 新增 due_at 字段到 tasks
- 旧 priority 保留为 legacy 字段
- 新 UI 使用 difficulty
- 旧数据默认 difficulty='medium'

## 专注功能新定位

- 左侧一级导航入口 /focus
- 主页面大型专注区域（12列布局，日程7-8列，专注4-5列）
- 状态机：ready → running → paused → completed → cancelled
- 基于时间戳计时，支持刷新恢复
- 同用户最多一个活动 session
- 与日程联动：任务卡片、详情均可"开始专注"
- 专注完成后累计到任务 actual_minutes
